# Design requirements

| ID | Design constraint | FRS |
|---|---|---|
| SRS-BB-001 | Domain rules are pure functions. They do not read the clock or database. Application services assemble facts and call the rule. | FRS-BB-030, FRS-BB-031 |
| SRS-BB-002 | `IssueGate` is the single issue-time rule aggregation point. Additional HardStops may be appended (dual ID, second-verifier directory) but must not replace the gate. | FRS-BB-031 |
| SRS-BB-003 | Electronic XM eligibility is computed by `ElectronicCrossmatchEligibilityService` / `ElectronicCrossmatchEligibilityRule` and reused by the patient workspace and issue pathway. An open antibody-identification workup is `XM-EC-ABID-OPEN` (HardStop). Serologic `RecordCrossmatchAsync` warns `ABID-XM-OPEN` and still records. | FRS-BB-033 |
| SRS-BB-004 | Assign and issue persist inside one unit-of-work. Unique filtered indexes enforce one active reservation and one open issue per unit. | FRS-BB-041 |
| SRS-BB-005 | AntibodyHistory, PatientBloodTypeHistory, InventoryStatusHistory, AuditEvent, and ElectronicSignature cannot be deleted through normal application saves. | FRS-BB-002, FRS-BB-060 |
| SRS-BB-006 | SQLite development databases apply additive columns/indexes via `DevelopmentSqliteBootstrap` so unique safety indexes exist on existing files. | FRS-BB-041 |
| SRS-BB-007 | Authorization is evaluated in the Application layer, not only in the UI. | FRS-BB-040 |
| SRS-BB-008 | ISBT raw scan, parsed fields, and display values are stored separately. | URS identity / ISBT docs |
| SRS-BB-009 | A merged (losing) patient is rejected at each clinical write path (accession, visit, order, result entry/verify/correct/invalidate, immunohematology, special requirements, allocate, XM, issue), not only at issue. | FRS-BB-003 |
| SRS-BB-010 | Result verification reuses the specimen entry gate (accepted, unexpired, surviving patient) before ABO/antibody history is posted. | FRS-BB-010, FRS-BB-003 |
| SRS-BB-011 | ADT, ORM, and inbound ORU resolve a merged MRN to the surviving patient (`PatientMergeFollow` / `FindByMrn` follow) before writing demographics, placing orders, or posting results. | FRS-BB-080, FRS-BB-003, FRS-BB-082 |

| SRS-BB-015 | Immunohematology writes are authorized inside `ImmunohematologyService`: `immuno.override` for manual ABO and antibody deactivate; `immuno.record` for antibody add and antigen profile. Callers that skip the API filter cannot change history used at issue. | FRS-BB-021, FRS-BB-002 |

A type-changing ABO/Rh verify after a completed in-scope workup warns `ABID-ABO-DONE` and does not reopen. Billing capture after save runs only when the result is Verified. | FRS-BB-022 |
| SRS-BB-017 | Special-requirement writes are authorized inside `SpecialRequirementService`: `immuno.record` to add; `immuno.override` to deactivate. The UI already hides those actions; the service is the control. An open workup warns `ABID-SR-OPEN` and does not block add or deactivate. | FRS-BB-023 |
| SRS-BB-018 | `LookbackService.RecallByDinAsync` checks `lookback.manage` when a permission evaluator is present, then fails closed if any `RecallForLookbackAsync` does not succeed. Reserved-state → Recalled is an allowed inventory transition. | FRS-BB-024 |
| SRS-BB-019 | Quarantine release is authorized inside `InventoryService` with `inventory.release`. Callers that skip the API filter cannot move a held unit to Available. | FRS-BB-052 |
| SRS-BB-020 | Directed-to-allogeneic conversion is authorized inside `InventoryService` with `inventory.release`. Callers that skip the API filter cannot clear the directed reservation. | FRS-BB-053 |
| SRS-BB-021 | Operational-hold release is authorized inside `InventoryService` with `inventory.release`. Callers that skip the API filter cannot move a held unit to Available. | FRS-BB-054 |
| SRS-BB-022 | Result verify and unit retype verify are authorized inside `ResultService` and `ProductRetypeService` with `result.verify`. Callers that skip the API filter cannot establish current type or move a unit to Available. | FRS-BB-055 |
| SRS-BB-023 | Allocation and crossmatch are authorized inside `CompatibilityService` with `compatibility.allocate` and `compatibility.crossmatch`. The patient workspace allocate path uses the same service. | FRS-BB-056 |
| SRS-BB-024 | `IssuingService.IssueUnitAsync` requires `issue.create` before the issue gate. Emergency/MTP still requires `issue.emergency-release` in addition. | FRS-BB-057 |
| SRS-BB-025 | Result enter and in-place update are authorized inside `ResultService` with `result.enter`. Verified-result correction requires `result.correct`. | SRS-BB-058 | Antibody-identification assistance is a pure Domain evaluator. Application stores assist findings as `AntibodyIdSource.Assist`/`History` and never posts them to `AntibodyHistory`. A completed in-scope workup skips free-text or blood-attribute antibody history changes (`ABID-WORKUP-AUTHORITATIVE` / `ABID-WORKUP-DISAGREE`). `EvaluateSpecimenRejectedOpenWorkup` warns `ABID-SPEC-OPEN` on reject; `AppliesToOpenWorkup` treats a rejected or cancelled linked specimen as patient-wide until void or re-link. `EvaluateOverlappingOpen` HardStops another workup (`ABID-WORKUP-DUP-OPEN`) when `hasOpenOnUnusableSpecimen`; `IsPatientWideIdentificationScope` includes rejected, cancelled, expired-status, clock-expired, Received (not yet accepted), and Collected (not yet received). named lots still use `/antibody-id?lot=`. `MatchesWithdrawnJudgment` filters `/antibody-id?withdrawn=1` when `EvaluateJudgmentWithdrawnReason` is set (`HasWithdrawnJudgment` / `WithdrawnJudgmentCount`). `MatchesPendingTypeCorrection` filters `/antibody-id?typePending=1` using `PendingTypeCorrectionApplies` (`HasPendingTypeCorrection` / `PendingTypeCorrectionCount`). `MatchesOpenProducts` filters `/antibody-id?products=1` when the patient has a reserved allocation or issued unit (`HasReservedOrIssuedUnits` / `ReservedOrIssuedUnitCount`). `EvaluateSpecimenEditedOpenWorkup` warns `ABID-SPEC-EDIT` when collection or expiration changes. `EvaluateManualHistoryDeactivatePostedWorkup` warns `ABID-DEACT-POSTED` when the row was posted by a completed workup; phenotype is not auto-reverted. `RecordBloodTypeManualAsync` and ABO/Rh `VerifyResultAsync` warn `ABID-ABO-OPEN` and withdraw when ABO/Rh changes. `InvalidateResultAsync` of a verified ABO/Rh result warns `ABID-ABO-INVAL` and withdraws; posted blood-type history is not auto-reverted. `CorrectResultAsync` of ABO/Rh or patient antigen while a workup is open warns `ABID-TYPE-CORR` and does not withdraw. `EvaluatePendingTypeCorrection` HardStops complete and Accept (`ABID-TYPE-PENDING`) until the current `Corrected` row is verified or invalidated; a scoped workup checks the linked specimen only. `EvaluateAntigenCompletedWorkup` / `EvaluateBloodTypeCompletedWorkup` warn `ABID-AG-DONE` / `ABID-ABO-DONE` on an in-scope type change after complete (same-specimen verify;
