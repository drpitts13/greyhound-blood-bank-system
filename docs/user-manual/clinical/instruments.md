![Instrument interfaces](figures/instruments.png)

**Instrument Interfaces** shows the status of ASTM instrument connections and their recent messages. You need permission to manage instruments. The mapping of instrument tests onto LIS tests, and the if/then rules, are configured in Administration. The help panel on that administrator screen is the field reference. This page tells you whether messages are arriving. Each instrument's status says when it last sent a message and how long ago (*Last message 2026-11-17 21:10 (2 d ago)*), or *No message received yet*: an instrument that is listening but has been silent longer than your bench expects may have lost its link.

The Messages list counts failed messages that are still open. Open one to see why it failed. Fix the cause (for example place the missing order) and choose **Replay**: when the replay applies, the failed message is marked resolved by that replay. If you handled it another way, such as entering the result by hand, give the reason under **Resolve without replay**. Replay is offered only for an open failed message, so results that already filed are never filed again.

An open failure says what to do next and links to where to do it: a test not ordered on the specimen links to the patient (**Find patient**), where the test is ordered before **Replay**; when that specimen has expired since, it says instead that the result can no longer be posted to it (except to a transfusion reaction workup order) and to resolve the message, testing a new specimen if needed; a patient ID that is not the specimen's patient links to the specimen on Test Worklist and to the patient the instrument sent, to check the tube and its label; an instrument code with no translation links to **Unmapped values**.

When a result did not appear on the worklist, open the log for that instrument. A message that failed to map names the test or subtest code the instrument sent; a result for a test that is not ordered on the specimen says so; a result held for an instrument error code names the code. A result whose patient ID is not the specimen's patient is not posted (INST-PATIENT); the log names both. Check the tube label and the instrument's patient record before replaying. A result with no patient ID is posted by its specimen.

A result for one of the instrument's own QC samples (its sample ID starts with a QC sample ID prefix set for the instrument) shows as **QC sample**: nothing is posted to a patient and it is not a failure. Its Patient column reads *— QC*, since the patient ID an analyzer puts on its QC runs is not a patient (hover to see what the instrument sent). A QC run that failed as *No specimen matched* before the prefix was set closes when replayed. **Search** above the message list finds a specimen's messages, older ones included (the list otherwise holds the newest 200): type the specimen or patient id, or anything in the message, and press Enter. Show **All**, **Open failures**, or **Held** above the message list; the home screen card **Instrument failures** opens the open failures and says how many are held. A **held** result (marked Held) is one an instrument error or flag code kept off the record (the instrument's error code list says Hold). Replaying it holds it again. Check the reactions on the instrument and its QC, then either re-run the sample (and resolve this message once the new result has filed), or choose **Release held result** with the reason. The result then posts as pending verification, with the held code and who released it shown beside its source, and the message closes with your reason. Releasing needs result verification permission. **unmapped** beside Messages counts instrument codes with no translation and opens the list. A result for a specimen that has expired, was rejected, or is otherwise not accepted is refused with the same message you would see entering it by hand, including when the instrument re-sends a result it sent earlier. The earlier result is left as it was. Do not retype the result from the instrument printout and also leave the interface message to file later. You will have two results. Either replay after the map is fixed, or enter the result manually and resolve the interface message so it does not file again.

**When** shows the time for today's messages and the date and time for earlier ones, so a failure from yesterday is not read as today's. An open failure also says how long it has been **waiting**: its result has not reached the patient record for that long. Under its status, an open failure says why it failed (the full text is in the message and on hover), and the **Patient** column gives the patient id the instrument sent. When the instrument sends the same failing result again (same specimen, same reason), the later row says *Repeats message 8 (same specimen and reason)*: one fix (for example adding the missing order) covers both; replay or resolve each. The home card names the oldest wait (for example "oldest waiting 26 h").

An opened message shows the raw ASTM, the parsed data elements, the mapping of instrument codes onto LIS codes, and the **Rules** that ran on it as a table: each rule with its condition and what it changed (*subtest_result → 0*). The same rule making the same change several times in a row is one line with how many times (*× 5*). **Raw rule trace** below it shows the trace as recorded.

The simulator is a separate screen for sending a test message. Do not point it at a live instrument connection.

## Session logs

The session log lists connections, messages received and sent, and problems, newest first, 50 at a time. A listener start ("Listening on port …") is written each time the service starts; these are hidden unless you tick **Show listener starts** (the box gives how many there are). A listener that could not start (for example, the port is in use) is logged as an error and always shown. Tick **Warnings and errors only** to see just the problems. With more than one instrument, choose one or All instruments, and each row names its instrument.
